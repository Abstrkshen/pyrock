Playground

Write Python and compile it with pyrock in your browser. This is the real compiler, built to WebAssembly: you get the same diagnostics, inferred types, CPython boundaries and Rust code as pyrock check, explain and emit print on your machine.

Run the program to see its output. Compile shows what pyrock makes of it without running it.

pyrock explain: imports, inferred generic signatures, specializations and CPython boundaries.

Compiling

The pyrock compiler from this repository (crates/playground), built to WebAssembly. Inference, specialization, the boundary list and Rust code generation all run in your browser.

Parsing

As on your machine, pyrock parses with CPython's own ast module. Here that CPython is Pyodide (Python 3.12 in WebAssembly), loaded once, about 10 MB.

Running

The generated Rust needs Cargo to become a program, and a browser has no Cargo. So Run executes your code with CPython in Pyodide. A program compiled by pyrock prints the same output; its test suite checks that for every feature.

Pictures from printed output

Print SVG or HTML and the Output tab draws it. Print several <svg> documents one after another and they play as an animation, one frame each. Print a plain-text PPM image (P3, then width, height, maximum value and an r g b triple per pixel) and it's painted on a canvas; several in a row animate too. Because a picture is just text the program prints, the native executable pyrock builds prints exactly the same one: open it in a browser, or save it as .svg, .html or .ppm. The graphics examples all compile with --mode native-only.

One file only: other imports go to CPython (the standard library works, and Pyodide's packages such as numpy load on first import). Where pyrock documents a difference from CPython, the output here is CPython's: for example, integers beyond 64 bits raise OverflowError in a compiled program. For the native executable, install pyrock and run pyrock run main.py.
